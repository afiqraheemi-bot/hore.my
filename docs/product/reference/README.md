# hore.my Authoritative Project References

This directory contains the authoritative reference documents for hore.my.

When instructions or requirements conflict, apply the following order of precedence, from highest to lowest:

1. Latest Founder instruction
2. `HORE_MY_PROJECT_INSTRUCTIONS.txt`
3. `HORE_MY_MASTER_CONTEXT.md`
4. System Requirements Specification (`hore.my_Spesifikasi_Keperluan_Sistem_v1.0_BM.pdf`)
5. Detailed Project Proposal

The latest applicable source at the highest precedence level governs. Record any consequential conflict or interpretation in the relevant project documentation before relying on a lower-precedence source.

The historical source documents distributed as PDF (`hore.my_Spesifikasi_Keperluan_Sistem_v1.0_BM.pdf` and the Detailed Project Proposal) must be preserved in their original form. Updates to those sources must replace them only with newly authorized source versions; editorial corrections, reformatting, or content changes must not be made locally.

The reference text documents maintained in this repository (`HORE_MY_PROJECT_INSTRUCTIONS.txt` and `HORE_MY_MASTER_CONTEXT.md`) may receive narrow, Founder-approved controlled revisions when a specific normative statement they carry has been superseded by a later Founder decision, such as a technology lifecycle correction. Each such revision must be limited to the superseded statement, must not change product scope, UX, or architecture on its own, and must be recorded in [`SRS_OVERRIDES.md`](SRS_OVERRIDES.md) together with the affected document, the original statement, the superseding decision, the authority, the effective date, and the reason. Superseding decisions are tracked in that log rather than edited into the immutable PDF sources.
